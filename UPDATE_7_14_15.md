# 7.14.15 — реляционный SQL backend, схема 12

Gateway проверяет схемы до 12 включительно и показывает реальный backend,
счётчики строк и результат полного обратного чтения при миграции.

relational_store.py — самостоятельный HA Store-совместимый адаптер. Его одинаковые
копии устанавливаются вместо _relax47_sql_store.py в восьми уже мигрированных
компонентах. Само обновление Gateway не меняет действующие HA-компоненты или БД.

Переключение выполняется при контролируемом перезапуске после резервной копии.
Адаптер проверяет совпадение SHA всех восьми файлов до первого переключения.
В одной транзакции он сохраняет исходные снимки и переносит действующие SQL
документы в stays, vehicles, pass_requests, passes, gate_events, events,
stay_violations и отдельные строки runtime_fields/runtime_items для настроек,
очередей, уведомлений и остальных коллекций. Старые runtime_documents замораживаются;
после переключения они не читаются и не используются для записи.

Исходные JSON-поля отдельных записей сохраняются полностью ради совместимости
старого UI и бизнес-модулей; это не замена интерфейса, тарифов или транспортов.
Связи контролируются внешними ключами. Старинные неразрешённые ссылки сохраняются
в runtime_unresolved_links, а новые несуществующие ссылки отклоняются.
Административные/неизвестные пропуска допускают NULL stay_id с явным context_kind.
Несколько исторических vehicle_id одного номера не сливаются автоматически.

Перед commit выполняется полное обратное чтение всех восьми исходных envelopes,
foreign_key_check и quick_check. Ошибка откатывает всю миграцию вместе со схемой.
Запись использует CAS, транзакцию связанных строк и проверку обратного чтения.
Отмена coroutine дожидается commit/rollback executor и корректно обновляет ревизию.
Удаление элемента из рабочего списка не удаляет историческую доменную строку;
актуальная принадлежность определяется runtime_items.

Для аварийного обратного перехода предусмотрен явный rollback_to_compatibility:
он восстанавливает runtime_documents из текущих строк, сохраняя записи,
созданные после переключения. Требует остановки других писателей и восстановления
восьми прежних адаптеров до запуска HA. Старый backup нельзя накладывать поверх
новых данных. Схема 12 и история при таком откате сохраняются.

Миграция не вызывает сервисы оборудования, не отправляет сообщения, не повторяет
очередь провайдера и не переносит бинарные медиа. Ссылки и метаданные сохраняются.

Проверки: 14 SQLite/async integration tests — полная сверка, создание новых связей,
неизменность исторических ID, перезапуск адаптера, повторный запуск, конфликт CAS,
отмена записи, откат ошибки схемы, откат с новыми данными, неполная установка,
неразрешённые новые FK и 1500 записей уведомлений.

При отказе миграции схема полностью откатывается; модули продолжают работать с
исправным SQL schema11. Ошибка явно показывается в migration status. Повторные
попытки того же адаптера блокируются; исправленный SHA допускает новый перенос.
