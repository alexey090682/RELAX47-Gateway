# 7.14.16 — подключение шлюза от пользователя Home Assistant

Исправляет возможность авторизовать шлюз под выбранным пользователем, когда служебный аккаунт Supervisor распознаётся RELAX47 как guest. Это обычное обновление существующего дополнения; ZIP Admin Access 1.0 не требуется и RBAC не меняется.

## После обновления

1. Войти в Home Assistant под владельцем (Alexey090682) либо пользователем, которому владелец уже назначил нужную роль RELAX47.
2. Открыть свой профиль → Безопасность → Долгосрочные токены доступа. Создать токен с названием «RELAX47 Gateway». Это ключ API, а не пароль аккаунта.
3. Открыть Настройки → Приложения → RELAX47 Local Gateway → Конфигурация. В поле «Ключ доступа пользователя Home Assistant» (`ha_user_token`) вставить созданный ключ. В чат ключ не отправлять.
4. Сохранить настройки и перезапустить только шлюз. Проверить «Подключение к Home Assistant» на странице шлюза; режим должен стать «учётная запись пользователя».
5. Проверить отправку уведомления через обычный сервис RELAX47 и статус доставки. Подключение API само по себе не подтверждает права RELAX47 или доставку в MAX.

Если нужен отдельный аккаунт, его создаёт владелец в Home Assistant и отдельно назначает роль administrator в RELAX47. Галочка администратора HA сама по себе эту роль не даёт. Для существующего владельца дополнительное назначение не требуется. Токен владельца передаёт шлюзу права владельца, а не только право рассылки; выбирайте пользователя с необходимыми правами.

## Отзыв и ошибки

Удалить токен в профиле Home Assistant — новые запросы с ним будут отклоняться. Удалить его из настроек дополнения и перезапустить шлюз — вернётся прежнее служебное подключение. При 401/403 проверить действительность ключа и права пользователя; автоматического переключения на другой аккаунт нет.

Пустое поле по умолчанию сохраняет текущий режим. Публикация и установка обновления не авторизуют шлюз от имени владельца. Ключ вводится пользователем в защищённом интерфейсе конфигурации дополнения, не принимается аргументами MCP. Значение не выводится на странице шлюза или в статусе. HTTP-перенаправления запросов к Core запрещены, чтобы ключ не ушёл на другой адрес. Запросы Supervisor (обновления/backup) по-прежнему используют только служебную авторизацию.

Основа: https://developers.home-assistant.io/docs/auth_api/#long-lived-access-token

Проверки: тесты выбора удостоверения, отказа без fallback, разделения Core/Supervisor, отсутствия ключа в статусе, запрета перенаправлений; существующие тесты public MCP и безопасности релиза. Реальный вход с пользовательским ключом проверяется после его ввода владельцем.
