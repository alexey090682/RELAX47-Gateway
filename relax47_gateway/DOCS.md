# RELAX47 Local Gateway 7.14.0 — автономное администрирование

Версия 7.14.0 исправляет совместимость Streamable HTTP с Claude, Claude Code,
ChatGPT и программными клиентами. Каждое подключение получает отдельный
`Mcp-Session-Id`; чтения выполняются независимо, конфликтующие записи проходят
через единую очередь. OAuth и существующие функции 7.12.0 сохранены.

Версия сохраняет защищённый сбор local keys из уже авторизованной официальной Tuya и
защищённый сбор local keys из уже авторизованной официальной Tuya и сохраняет
безопасную автоматизацию Tuya → LocalTuya. Каждое новое устройство создаётся в
отдельной записи LocalTuya, поэтому ошибочная миграция откатывается без влияния
на уже работающие устройства. Облачная Tuya автоматически не отключается.

После однократной установки этой версии последующие архивы передаются через
MCP частями с обязательной проверкой размера и SHA-256. Шлюз умеет загрузить
backup в Supervisor, восстановить выбранные компоненты, обновить себя и другие
дополнения. Для изменений конфигурации `/homeassistant` используется только
транзакционный путь: страховочный backup, атомарная запись, `core/check` и
автоматический откат. `.storage`, `secrets.yaml`, credentials и база данных
напрямую не читаются и не передаются в чат.

Home Assistant, пароль роутера, ключи Tuya и код активации остаются внутри
локального дополнения. ChatGPT получает короткоживущий OAuth-токен только после
того, как владелец самостоятельно введёт локальный код на странице авторизации.

## Установка обновления

1. Восстановите этот TAR как частичный бэкап.
2. Обновите список локальных дополнений.
3. У RELAX47 Local Gateway нажмите **Пересобрать** / **Обновить**.
4. В конфигурации сохраните пароль AX6000 и установите:

```yaml
write_mode: true
auto_verify_writes: true
secure_mcp_enabled: false
public_mcp_enabled: true
public_mcp_port: 8766
public_base_url: https://relax47-home.duckdns.org
oauth_activation_code: ВАШ_ЛОКАЛЬНЫЙ_КОД_НЕ_КОРОЧЕ_12_СИМВОЛОВ
oauth_token_hours: 12
public_rate_limit_per_minute: 120
public_max_request_bytes: 2097152
public_session_hours: 12
ssh_enabled: false
reverse_ssh_enabled: false
```

Код активации придумайте самостоятельно. Не отправляйте его в чат. Файлы
DuckDNS/Let's Encrypt `/ssl/fullchain.pem` и `/ssl/privkey.pem` должны уже
существовать.

После запуска в журнале должна появиться строка:

```text
Public HTTPS MCP started on internal port 8766
```

## Правило Xiaomi AX6000

Существующее правило MCP должно оставаться:

- протокол: TCP;
- внешний порт: `443`;
- внутренний адрес: `192.168.31.202`;
- внутренний порт: `8766`.

Обновление 7.13.0 не изменяет WAN, DMZ, публичные порты и облачную Tuya.

Проверка доступности:

```text
https://relax47-home.duckdns.org/healthz
```

Сервис должен вернуть JSON с `"ok": true` и версией `7.14.0`.

## Автономная работа ChatGPT и Claude

После выдачи scope `mcp:admin` доступны безопасный диагностический терминал,
Supervisor/host/Core/network inventory, чтение и транзакционная правка
конфигурации, передача файлов, backups, управление приложениями, проверка и
перезапуск Core. Интерактивный root shell наружу не публикуется: terminal_exec
не использует shell и допускает только read-only команды. Секреты, `.storage`,
TLS private keys и host internals остаются недоступными, а каждая изменяющая
операция содержит клиента, сессию, причину и результат в аудите.

## Подключение Claude

В Claude Web добавьте Custom Connector с URL
`https://relax47-home.duckdns.org/mcp` и завершите авторизацию на странице
RELAX47. Для Claude Code:

```sh
claude mcp add --transport http relax47 https://relax47-home.duckdns.org/mcp
```

Локальный callback Claude Code по HTTP разрешён только для loopback-адресов;
любой публичный callback по HTTP отклоняется.

## Подключение в ChatGPT

1. На `chatgpt.com` откройте **Настройки → Безопасность и вход**.
2. Включите **Режим разработчика**.
3. Откройте **Плагины**, нажмите `+` и создайте MCP-подключение.
4. Имя: `RELAX47 Home`.
5. URL: `https://relax47-home.duckdns.org/mcp`.
6. Подтвердите найденные инструменты.
7. На открывшейся странице RELAX47 самостоятельно введите код из
   `oauth_activation_code`.

После подключения список инструментов должен включать `ha_create_backup` и
группу `localtuya_*`.

## Безопасность

- MCP без OAuth возвращает `401` и не показывает данные дома.
- Поддерживается OAuth Authorization Code с PKCE S256 и динамической
  регистрацией клиента.
- Токен доступа действует от 1 до 168 часов; по умолчанию 12 часов.
- OAuth-коды одноразовые и действуют 5 минут.
- После пяти неверных кодов активации источник блокируется на 15 минут.
- Клиенты и сессии изолированы; чужой `Mcp-Session-Id` отклоняется.
- Действует per-client rate limit, ограничение размера запроса и срок сессии.
- Изменяющие запросы сериализуются; `Idempotency-Key` предотвращает повтор.
- Отдельный журнал соединений не содержит OAuth-токенов и других секретов.
- Секреты хранятся в `/data` с правами `0600`; в журнал не выводятся.
- Операции записи требуют `write_mode`, причины изменения, разрешённого домена,
  проверки чтением и записи в аудит.
- DHCP-изменения проверяются на конфликты и откатываются при неуспешной проверке.
- Local key не передаётся через MCP. `localtuya_sync_keys` читает уже
  авторизованную официальную Tuya и сохраняет ключи только в локальный файл
  `/share/RELAX47_TUYA_KEYS.json` с правами `0600`; наружу выходят лишь счётчики.
- Перед применением LocalTuya автоматически запрашивается резервная копия HA.
- Перед восстановлением, обновлением дополнения и правкой config создаётся
  страховочная резервная копия; изменение config проходит `core/check`.
- Шлюз получает роль Supervisor `manager` и write-mount `/homeassistant` только
  для перечисленных аудируемых операций с проверкой и откатом.
- Проверка управления допускается только для явно некритического света или
  выключателя и всегда возвращает исходное DP-состояние.

## Доступные группы инструментов

- Home Assistant: состояние, реестры, сущности и разрешённые сервисы.
- Xiaomi AX6000: авторизация, клиенты, DHCP, сетевое состояние.
- LAN: ARP/neighbor и ограниченное сканирование заданной подсети.
- Tuya/LocalTuya: сводка, защищённый сбор ключей, DP-проба, подготовка,
  создание/обновление, пакетное продолжение после ошибки и откат устройства.
- Maintenance: chunk-upload, backup list/restore, addon install/update/restart,
  автономное самообновление, безопасное чтение и транзакционная правка config.
- Аудит и полный экспорт инвентаризации.

Изменение WAN forwarding и DMZ по-прежнему не выполняется вслепую. Сначала
шлюз читает фактические методы RA72 и возвращает доступную поверхность API.
