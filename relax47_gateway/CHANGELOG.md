# 7.14.11

- Добавлена sql_prepare_runtime_migration: закрытый локальный SQL-снимок восьми
  явно разрешённых Store RELAX47, без передачи значений и секретов в MCP.
- Перед снимком: проверенный backup, согласованная остановка Core и внешних
  писателей. Проверяются полные исходные JSON-конверты, точное обратное чтение,
  неизменность источников и SQLite integrity/FK. Исходники не удаляются.
- Результат в /data/sql_candidates/<candidate_id>.db с правами 0600; каталог 0700.
  Это сохранение исходных данных в runtime_documents, НЕ нормализация таблиц
  stays/passes и НЕ переключение живых модулей. Медиафайлы не копируются.
- Чтение auth, core.config_entries, secrets.yaml и произвольных файлов по-прежнему
  запрещено. Отсутствующие необязательные Store отражаются в отчёте.
- Добавлена maintenance_backup_retention: явное включение ежедневной очистки
  с хранением трёх последних и protected/NEVER DELETE. По умолчанию выключена.
  Настройка переживает перезапуск, первый запуск через 24 часа после включения.
  Не выполняется при write_mode=false или одновременно с SQL-операцией.

# 7.14.10

- Поддержка SQL-схем RELAX47 10 (сохранение данных) и 11 (медиа заездов).
- Версии 10–11 принимаются только при соответствии обязательных таблиц,
  индексов и представлений эталонным SQL-определениям. Дополнительные объекты
  не удаляются. Обход проверки изменением schema_version не допускается.
- Эталоны schema-10.sql/schema-11.sql взяты из подготовленного ядра RELAX47 8.0;
  они не содержат гостевых записей и не исполняются на пользовательской базе.
- Запрет понижения схемы при установке; сохранены backup/rollback, SHA-256,
  quick_check, integrity_check, foreign_key_check, остановка/запуск Core.
- Статус сообщает поддерживаемую схему даже до установки SQL-базы.
- Сохранены OAuth/MCP, ограниченный терминал, очистка backup с минимум тремя
  последними и защищёнными копиями; права доступа не расширены.
- Обновление шлюза НЕ переносит JSON Store и НЕ переключает интеграции на SQL.
  Нужны свежий экспорт, проверенные адаптеры и отдельное окно переключения.

# 7.14.9

- Публикация Gateway как отдельного Home Assistant repository.
- Существующие инструменты LAN, роутера, HA, Tuya, OAuth/MCP и SSH сохранены.
- SQL status/inspect/install для единственной RELAX47 БД; SHA-256 и SQLite checks.
- SQL install требует согласованного обслуживания и остановки внешних writers;
  управляет остановкой/запуском Core через Supervisor после проверенного HA backup.
- SQLite backup transaction вместо замены inode; backup/rollback, межпроцессная блокировка.
- Generic config upload не применяет базы в обход SQL-проверок.
- SQL и backup cleanup доступны только административным MCP-токенам.
- Очистка backup: dry-run по умолчанию, минимум три последних и protected сохранены.
- Dockerfile включает sql_migration.py. Кэши Python исключены.
- Установка из репозитория не использует старое самообновление local_relax47_gateway.

Совместимость схемы SQL: 1–9. Полная миграция бизнес-данных и боевой запуск в этот
релиз публикации не входят. Инструкции перехода и отката — в корневом README.
