# Gateway 7.14.13: проверка второго этапа SQL

Первая миграция сохраняет восемь HA Store в runtime_documents. Она не заполняет
нормализованные бизнес-таблицы. До следующего переноса необходимо проверить
актуальные SQL-документы, поскольку сохранённые .storage-файлы уже устарели.

Вызов существующего sql_runtime_migration_status с include_normalization_plan=true
добавляет проверку согласованного read-only снимка: количества, форматы коллекций,
отсутствующие/повторяющиеся ID, неоднозначные даты и отсутствующие связи. Данные
гостей, номера автомобилей, тексты очередей и секреты не выводятся. Нет новых
прав записи и новых инструментов MCP. Обычный вызов статуса остаётся прежним.

Проверка не меняет данные, не запускает сообщения/ворота/видеогенерацию и всегда
возвращает cutover_ready=false. Это диагностика подготовки, не нормализатор.
Она не проверяет все бизнес-правила, наличие файлов медиа и UI parity.

Проверено: python -m unittest discover -s relax47_gateway -p 'test_*.py'
— 56 тестов успешно. После установки проверить версию, RUNNING HA, вызвать
расширенный статус и сохранить результат проверки без приватных строк.
