# RELAX47 Gateway Repository

Штатный Home Assistant app/add-on repository для RELAX47 Gateway **7.14.11** (amd64).

URL для Home Assistant:

```text
https://github.com/alexey090682/RELAX47-Gateway
```

В корне находится `repository.yaml`, исходники приложения — в `relax47_gateway/`.

## Переход с local_relax47_gateway

1. Создайте и проверьте резервную копию текущего приложения, его конфигурации и данных.
2. В Home Assistant: **Настройки → Приложения (Дополнения) → Магазин → ⋮ → Репозитории**.
   Добавьте URL выше. Если карточка не появилась — обновите магазин.
3. Установите **RELAX47 Local Gateway 7.14.11** из раздела **RELAX47 Gateway Repository**.
   Пока не запускайте его. Существующий local_relax47_gateway не удаляйте.
4. Перенесите настройки старого приложения в новое средствами HA; пароли и ключи
   вводите в конфигурации HA, не публикуйте их в GitHub или чате. Для RELAX47 оставьте
   `secure_mcp_enabled: false`, если используется прямой публичный HTTPS MCP.
   Проверьте сертификаты и параметры публичного адреса.
5. У приложений разные идентификаторы и отдельные каталоги `/data`.
   Настройки, OAuth-сессии, история аудита и незавершённые загрузки автоматически не переносятся.
   Сохраните старое приложение для доступа к прежним данным. Клиентам нового шлюза
   потребуется повторная OAuth-авторизация, если состояние OAuth отдельно не переносилось.
6. В согласованное окно переключения отключите автозапуск и watchdog старого шлюза,
   **остановите** его, затем запустите новый. Одновременно оба не запускайте:
   используются общие сетевые порты (в том числе ingress 8099).
7. Проверьте журнал запуска, фактическую версию процесса **7.14.11**, интерфейс ingress,
   Home Assistant API, OAuth/MCP, чтение SQL-статуса. После проверки включите нужные
   параметры автозапуска нового приложения. Старое пока сохраняйте установленным.
8. При ошибке остановите новое приложение и запустите старое, восстановив его
   автозапуск/watchdog. Не восстанавливайте SQL наугад: установка Gateway сама базу не меняет.

`ha apps update local_relax47_gateway` не переводит локальное приложение на GitHub.
После перехода последующие версии устанавливаются кнопкой **Обновить** в карточке
нового приложения. Его идентификатор выдаёт Supervisor; он отличается от `local_...`.

## SQL и обслуживание

### Подготовка локального переноса (7.14.11)

`sql_prepare_runtime_migration` принимает change_reason, stop_home_assistant=true
и confirm_other_writers_stopped=true. Это реальная остановка Core на время снимка;
внешние писатели должны быть предварительно остановлены оператором.
Команда не должна запускаться автоматически по расписанию.

Разрешены только: relax47_guest_journal.runtime, relax47_pass_gateway.runtime,
relax47_zone_access.runtime, relax47_ai.runtime, relax47_stage75.runtime,
relax47_integrations.runtime, relax47_rbac.roles, relax47_realtycalendar.runtime.
Снимок хранит полные исходные Store-конверты в таблице runtime_documents
(item_key=source_envelope). В MCP возвращаются только идентификатор снимка,
число Store, отсутствующие Store, контрольная сумма и результаты проверки.
Секретные значения остаются на сервере в приватной БД; её нельзя публиковать.
Данные других хранилищ и файлы фотографий/видео этим этапом не покрываются.

Рабочая база и JSON-источники не меняются. Этот результат ещё нельзя считать
полной миграцией: требуются адаптеры действующих модулей, сохранение связей,
сверка данных и отдельное переключение. Часовой пояс свойства снимка UTC —
техническая заглушка; исходные даты/настройки сохраняются буквально, без конверсии.

### Автоматическая очистка

После обновления включите `maintenance_backup_retention` с enabled=true и
change_reason. Первый запуск — через 24 часа, затем раз в 24 часа; расписание
сохраняется в /data/backup-retention.json. Для выключения передайте enabled=false.
Обслуживание выполняет сам Gateway, не внешний чат. Очистка оставляет последние
три копии любого типа плюс protected/NEVER DELETE; поэтому защищённые копии могут
увеличить итоговое число. Перед удалением учитывайте, что частичная копия отдельного
дополнения не заменяет полную копию HA. Удаление через Supervisor необратимо без
отдельной внешней копии. Google Drive этим механизмом не настраивается.

### Установка SQL

- Единственный SQL-target: HA `/config/relax47_v8/relax47.db`, внутри контейнера
  `/homeassistant/relax47_v8/relax47.db` (существующее сопоставление каталога сохранено).
- `sql_database_status` проверяет согласованный SQLite snapshot, включая WAL.
  Возвращает метаданные и количества строк; содержимое строк не раскрывается.
- `sql_inspect_upload` принимает завершённую конфигурационную загрузку с target_path
  `relax47_v8/relax47.db`. Проверяются размер, SHA-256, quick_check, integrity_check,
  foreign_key_check и RELAX47 schema_version **1–11**. Более новая/неизвестная схема
  отклоняется; совместимость с ней нельзя подтвердить сменой номера в настройке.
  Для схем 10–11 дополнительно сравниваются определения всех обязательных таблиц,
  индексов и представлений с эталонами в `relax47_gateway/sql_schemas/`.
  Эталоны содержат только структуру, без гостевых данных. Изменённые определения
  отклоняются (включая форматирование SQL); дополнительные объекты сохраняются.
  Схемы 1–9 сохраняют прежнюю проверку идентификатора и целостности.
  Понижение версии установленной SQL-схемы запрещено; автоматический откат
  неудачной установки к её собственной резервной копии остаётся доступен.
  Статус отсутствующей базы также сообщает `supported_schema_version: 11`.
- `sql_install_upload` требует ожидаемый SHA-256, причину изменения,
  `stop_home_assistant: true` и `confirm_other_writers_stopped: true`.
  Оператор заранее останавливает другие приложения/скрипты, работающие с этой базой,
  и согласует перерыв в автоматизациях. Шлюз сначала проверяет HA backup, затем
  останавливает Core через Supervisor, сохраняет отдельный SQLite backup,
  устанавливает через SQLite backup transaction, проверяет результат и запускает Core.
  При ошибке после записи выполняет откат; при ошибке отката Core остаётся остановленным.
  Это установка подготовленной БД, **не преобразование всех старых заездов в SQL**.
- SQL backups находятся в `/data/sql_backups` нового приложения, не очищаются
  автоматически. SHA-256 загруженного файла возвращается как `source_sha256`;
  SQLite может изменить служебный заголовок целевого файла при транзакционном копировании.
- `maintenance_backup_cleanup` по умолчанию делает только dry-run. Минимум 3 последних,
  `protected: true` и имена с `NEVER DELETE` сохраняются. Флаг Supervisor `protected`
  не следует отождествлять с отдельной отметкой «хранить бессрочно» стороннего Drive-приложения:
  для таких копий добавьте `NEVER DELETE` в имя перед очисткой через Gateway.
- SQL-инструменты и очистка backup требуют административного OAuth scope;
  запись дополнительно проверяет write-mode и установленный confirmation_code.
- Для установки из GitHub используйте обновление Store. Старый механизм восстановления
  `addons/local` разрешён только самому `local_relax47_gateway`.

## Проверки и границы

```sh
python3 -m unittest discover -s relax47_gateway -p 'test_*.py'
bash -n relax47_gateway/run.sh
```

Тесты используют временные SQLite-базы и подменённые ответы Supervisor;
они не заменяют запуск контейнера на HA. Полная Docker-сборка и проверка на боевом
объекте обязательны при установке. Исходный архив: SHA-256
`3050484548eb6b2bc671dbe80c089e6f976af621f56913b25343a6fa0b230358`.

Упаковка исправлена: SQL-модуль включён в Dockerfile, build-аргументы доступны
в финальном этапе образа. Кэши Python из ZIP не публикуются.

Официальная структура репозитория: https://developers.home-assistant.io/docs/apps/repository/
